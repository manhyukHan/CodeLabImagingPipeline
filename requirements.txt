# Dependencies for the `code_lab_imaging_pipeline` conda env. launch_codelab.bat /
# launch_codelab.command create that env from THIS file automatically the
# first time they find it missing, so this list is the single source of
# truth -- add a dependency here, not into an env by hand.
#
# torch is pulled from PyTorch's own CUDA 11.8 index rather than PyPI:
# segmentation/segment.py asks cellpose for gpu=True, and the default PyPI
# torch wheel on Windows is CPU-only, which silently costs an order of
# magnitude on every segmentation. Machines with no NVIDIA GPU still work
# -- the same wheel falls back to CPU at runtime.
--extra-index-url https://download.pytorch.org/whl/cu118

# THIS CHANGES THE SEGMENTATION, not just the package. cellpose 4 deleted
# models.Cellpose and the cyto3 weights with it; the model here is now
# cpsam, a different network. Cell counts, boundaries and every trace
# downstream of them WILL differ from anything segmented under 3.x. Results
# already in a store were produced by cyto3 and are not reproduced by this
# line -- to reproduce them, pin `cellpose==3.1.1.3` instead. segment.py
# supports both and dispatches on the installed version
# (segmentation/segment.py:15-80), so that pin needs no code change.
#
# MEASURED, both real packages driven through segment.py's own dispatch on
# an RTX 3070, back to back, 1024x1024 synthetic field (the real MIP size),
# 90/90 blobs found by both, three timed repeats each:
#                        model load   first eval   steady eval
#     3.1.1.3 (cyto3)      6.77 s       2.54 s       0.69 s
#     4.2.1.1 (cpsam)      6.48 s       1.73 s       1.12 s
# Read that as: LOAD IS A WASH -- the 46x weight-size difference does not
# become a 46x load, or even a 2x one -- and cpsam is about 1.6x SLOWER per
# segmentation, not faster. Model load and the first eval are paid once per
# PROCESS (segment.py caches the model in a module singleton), so the
# surcharge is ~8 s per app launch, not per FOV.
#
# An earlier 512x512 pass appeared to show cpsam 5x faster. It was
# confounded: the two arms ran with different CUDA/file-cache warmth. Those
# numbers are withdrawn; these replace them. Even these are one synthetic
# image and are not a benchmark of real FOVs.
#
# The weights are NOT pinned by this line -- cellpose downloads them on
# first use and the package version does not determine them. cpsam is
# ~1.2 GB against cyto3's 26 MB, downloaded once per MACHINE into
# ~/.cellpose/models/ and cached there. REFERENCES.md records the hashes.
cellpose>=4.2,<5

# cellpose 4 needs it (Requires-Dist), cellpose 3 did not. Pinned +cu118
# for the same reason torch is, and to the version built against
# torch 2.7.1 -- a mismatched torchvision drags in its own torch and
# quietly undoes the CUDA pin below.
torchvision==0.22.1+cu118

# The cu118 torch wheels are built against the numpy 1.x ABI; this matches
# the interpreter this project is known to run on today (numpy 1.26.4).
# cellpose 4 asks only for numpy>=1.20, so it does not force this open.
numpy<2

# Pinned WITH the +cu118 local version on purpose. --extra-index-url only
# ADDS an index; pip still picks the highest version it can see anywhere,
# and plain "torch" resolved to PyPI 2.13.0 -- which on Windows is
# CPU-only (verified: torch 2.13.0+cpu, torch.cuda.is_available() False).
# A "+cu118" version exists on no other index, so naming it forces the
# CUDA wheel. 2.7.1 is the newest build the cu118 index carries, and it
# is newer than anything on the cu121/cu124 indexes.
torch==2.7.1+cu118
pandas
openpyxl
h5py
opencv-python

# Optional, but preprocess.total_ram_bytes prefers it when deriving the
# ingestion worker ceiling (it falls back to a Win32/POSIX call without it).
psutil

# Lets parallel.py pin a worker's BLAS to one thread even when numpy is
# already imported, which the environment variables alone cannot do -- by
# then they have missed their chance. Without it, N worker processes each
# size their BLAS pool from the whole machine: on a 32-core box that is 32
# processes asking for 64 threads apiece. It is also what lets the tests
# ASSERT the pinning rather than assume it. Falls back to env-only.
threadpoolctl

# The GUI itself.
PyQt5
